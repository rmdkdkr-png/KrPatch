# 받침 타이핑 — 코드패치 조사 최종보고

## 결론

**데이터로는 불가능합니다. 확정했습니다.**
대사 렌더러는 **글리프 레코드에서 타일을 한 장만 읽습니다.**

## 알아낸 주소 (다음 사람용)

    대사 렌더러      CPU 0x20F82B   파일 0x00F82B
    글리프 표 포인터  파일 0x069968  →  원본 표 0x08FD2B
    확장 표(패치 후)  파일 0x1CBE45
    레코드 형식      [타일수 1B][타일 16B씩][행수 1B][행마다 타일인덱스…0xFF]
    행 맵 바이트     타일번호×2 + 좌우반전   (그래픽 타일맵과 같은 인코딩)

## 검증 과정

### 1단계 — 다중 행 레코드로 8×16 통짜 출력 시도

원본 코드 `0x96`·`0x97` 이 **2타일 2행 38B** 레코드입니다. 같은 형식으로
한글 음절 16종을 만들어 넣고, 6번 문장을 `F8` 없이 음절 코드만 나열했습니다.

결과: **윗줄 6칸 전부 픽셀 단위 일치. 아랫줄은 엉뚱한 타일.**

### 2단계 — 기하 구조 확인 (단일 문자 탐침)

윗타일 = 꽉 찬 블록, 아랫타일 = 테두리로 바꿔 넣고 관찰했습니다.

    1행: 대조 블록 대조 블록 …   ← 칸마다 정상, 커서도 1칸씩 정상 전진
    2행: 같은 칸 아래줄에 그려짐  ← **위치는 정확함**

**행 2 를 같은 칸 바로 아래에 그리는 것 자체는 됩니다.** 여기까진 좋은 소식입니다.

### 3단계 — 행2 맵 바이트 전수 시험 (결정적)

한 레코드에 타일 3장(꽉참 / 왼쪽3열 / 위3행)을 넣고
행2 맵 바이트를 `0x00`~`0x05` 로 바꿔가며 여섯 칸을 나란히 찍었습니다.

| 맵 바이트 | 기대 | 실제 |
|---|---|---|
| `0x00` | 타일0 | **타일0** ✓ |
| `0x01` | 타일0 반전 | **타일0** ✓ |
| `0x02` | 타일1 | 1px 왼쪽 막대 ✗ |
| `0x03` | 타일1 반전 | 1px 오른쪽 막대 ✗ |
| `0x04` | 타일2 | 타일0 ✗ |
| `0x05` | 타일2 반전 | 타일0 ✗ |

`0x02`와 `0x03` 이 **좌우 대칭**으로 나온 게 핵심입니다.
반전 비트는 정상 동작한다는 뜻이고, 그러면 인덱스 해석도 `바이트>>1` 이 맞습니다.
그런데 **인덱스 1 이상은 전부 쓰레기**입니다.

→ **텍스트 경로는 레코드에서 타일을 한 장(0번)만 로드합니다.**
말풍선 프레임(`0x95`, 6타일 4행)은 다른 코드 경로로 그리는 것으로 보입니다.

그래서 2행 레코드를 써도 **같은 타일이 두 번 찍힐 뿐**이라 쓸모가 없습니다.

## 두 번째 벽 — 코드 자리

설령 위가 됐어도 막힙니다.

    서로 다른 음절 392종  vs  쓸 수 있는 코드 약 244칸

빈도 상위 244음절에 코드를 다 줘도 267페이지 중 **161페이지(60%)** 만 덮입니다.

## 디버거는 못 씁니다

mednafen 을 붙여봤는데, **NGP 코어에는 디버거가 없습니다.**
설정 파일에 `md/nes/pce/pcfx/psx.debugger.*` 만 있고 `ngp.debugger.*` 가 없습니다.
토글 키를 수식키 없는 키로 재바인딩하고 `debugger.autostepmode 1` 까지 켜봤지만 열리지 않습니다.

TLCS-900H 디스어셈블러도 apt·pip·npm 어디에도 없습니다.
바이트를 손으로 해독해 롬에 써넣는 건 하지 않았습니다. 틀리면 조용히 깨지고,
그게 제일 나쁜 결과입니다.

## 그래서 남은 길

1. **TLCS-900H 디스어셈블러가 있는 환경에서 `0x00F82B` 를 읽는다.**
   고칠 지점은 둘 중 하나입니다.
   - 글자 하나 그릴 때 다음 스트림 바이트를 아랫줄 같은 칸에 그리고 커서는 1칸만 전진
     (데이터는 `t1 b1 t2 b2 …` 로 섞어 넣음) — 근본 해결, 코드 자리 문제도 사라짐
   - 타이핑 지연 제거 — 훨씬 간단, 연출이 바뀜
2. **그대로 두기.** 다 찍히고 나면 화면은 정상입니다.

## 부산물

조사 중에 확인한 사실 하나 — **한 줄 17칸은 정상적으로 한 줄에 들어갑니다.**
17칸짜리 시험 문장을 넣고 돌려 확인했습니다. 줄 넘침 문제는 없습니다.
