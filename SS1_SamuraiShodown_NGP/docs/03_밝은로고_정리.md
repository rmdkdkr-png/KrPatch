# 인트로 밝은 로고 (4벌째 자산) — v0.7 해결

v0.6 까지 인트로 애니메이션의 흰 배경 로고가 일본어 원문이었다.
기존 문서가 로고를 3벌로만 파악했기 때문. **4벌째가 있다.**

```
맵    file 0x08AA44   8행 × 16칸 (128×64px), 맵크기 137B
타일  file 0x08A3C4   104칸 (맵 직전까지가 예산)
로더  PC 0x200501 계열
```

## ⚠ VRAM 타일 인덱스 +0x20 시프트

VRAM 패턴램에서 역추적하면 타일 번호가 0x20 밀려 있다 (VRAM 0x42 → 레코드 0x22).
모르면 `spec()` 이 뽑은 타일 베이스와 실제 바이트가 0x200 어긋나 "파싱 실패"로 오판한다.

## 팔레트 역할이 본편 로고와 반대

| | 배경 | 외곽선 | 몸통 | 안쪽 음영 |
|---|---|---|---|---|
| 본편(어두운) | 3 | 0 | 2 | 1 |
| 인트로(밝은) | 0 | 1 | 2 | 3 |

역할 판정은 **배경 인접도**(외곽선일수록 배경과 맞닿는 비율↑)로 정량화했다.
두 자산은 크기·구도가 달라 값 대 값 자동 대응은 실패한다(전부 한 값으로 붕괴).

## 방식 (gfx11.py, 릴리즈 [15])

값 단순 치환은 획이 뭉개져서 **마스크 기반 재구성**:

1. 한글화된 본편 로고(A+B, 160×88)에서 잉크 마스크 추출
2. bbox 크롭 → 128×64 캔버스에 비율 유지로 채움 (여백 2px)
3. 원본 밝은 로고의 잉크 비중(≈56%)에 맞춰 임계값 자동 조정
4. 침식 2단계로 외곽선/몸통/안쪽 3층 → 밝은 팔레트로 페인트
5. 타일 전역 dedup 후 맵 재작성 (행·칸 수, 맵 크기 137B 불변)

**고유 타일 82/104 — 병합 없음.** 예산 초과 시 ValueError 로 중단한다(병합=획 붕괴).
