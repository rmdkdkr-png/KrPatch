## 1. 압축 손상 제거 — 25건 → 0건

`inject` 는 타일 예산을 넘으면 닮은 타일을 강제 병합합니다. **걸리면 획이 무너집니다.**
0.2 까지는 기존 `ITEMS`(화면 그림텍스트)와 전투 배너가 이 압축에 그대로 노출돼 있었습니다.
실제 피해 사례가 「아마쿠사 → 마마쿠사」, 「카즈키 → 가즈키」였습니다.

두 곳에 **예산 회피 렌더**를 붙였습니다. 한도에 들어갈 때까지
그림자 제거 → 폰트 한 단계 낮추기 → x 위치 미세조정 순으로 후보를 만들어 첫 통과안을 씁니다.

    빌드 로그 압축 발생  25건 → **0건**
    렌더 결과 = 롬 되읽기  **전 항목 일치** (압축이 아예 안 걸렸다는 직접 증거)

## 2. 너무 작던 글자 키움

원문 글자 높이 대비 한글 높이를 전 항목 측정해서, 60% 미만인 것만 손봤습니다.

| 자리 | 0.2 | 0.3 | 크기 |
|---|---|---|---|
| 断末奥義 / SPECIAL COMMAND | 마무리오의 | **오의** | 44% → 88% |
| 時間切れ / TIME OVER | 시간종료 | **시간 끝** | 56~60% → 69~73% |
| 勝負あり!! / CONCLUSION | 승부 끝!! | **결착!!** | 73% → 93% |

남은 60% 미만은 `LAST BATTLE → 최종전` 하나(56%)뿐입니다. 읽는 데 지장은 없습니다.

## 5. 눈으로 본 소견 (수정 안 함, 판단 필요)

- **「카즈키」의 ㅋ 중간 획이 얇습니다.** 8×16 에 그림자까지 얹히면 「가즈키」로 오독될 수 있습니다.
  롬 데이터는 「카즈키」가 맞는 걸 확인했습니다(기대 렌더와 픽셀 일치). 폰트 특성입니다.
- **「면허개전」**(免許皆伝)은 직역입니다. 「오의전수」 쪽이 한국 독자에게 익숙할 수 있습니다.
- **「勝負」(勝 `0x073CB7` + 負 `0x073EB1`)를 승/부로 넣은 건 근거가 약합니다.**
  라운드 전 콜로 봤는데, 실기 영문판에서는 그 자리에 `FAIR & SQUARE` 가 나옵니다.
  승패 표시일 가능성이 큽니다. 일본어 모드에서 확인해 보시고 어색하면 되돌리세요.
- 「연승 / 실력 / 그대의 등급」은 제가 정한 말입니다. 취향 확인 부탁드립니다.

## 6. 압축 폰트 — 추가 시도, 성과 없음

복원 목표를 알고 있다는 점(`0x05291D` 사본이 화면 폰트와 픽셀 단위 동일)을 이용해
계산만으로 두 갈래를 훑었습니다.

**(가) 시험 해제 스윕** — 롬 안의 3바이트 포인터가 가리키는 **26,142개 지점**에
LZSS 16종(리터럴 극성·비트순·오프셋 배치·링버퍼 조합) + RLE 를 적용해 3KB 씩 풀어보고,
`A B S M` 글리프 바이트가 나오는지 검사.
→ 일치 29건이 **전부 평문 뱅크 자기 자신**. 그 밖엔 0건.

**(나) 1bpp 저장 가설** — 뱅크에서 뽑은 정확한 `A`·`B`·`M` 비트맵으로
1bpp(MSB/LSB) · 반전 · 좌우반전 · 상하반전 · 전치, 2bpp(잉크=3 / 잉크≠0) 전수 탐색.
→ **전부 0건**.

**결론**: 표준 압축이 아니거나, 단순 포인터로 접근하지 않거나, 적재 시점에 형식이 바뀝니다.
계산만으로 뚫을 수 있는 범위는 여기까지입니다. 다음은 트레이싱 에뮬레이터 차례입니다.
