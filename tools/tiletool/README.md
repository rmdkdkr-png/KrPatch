# NGPC 타일 관측기 + 오프라인 시뮬레이터 (검수툴)

에뮬을 돌리며 **화면에 실제로 뜬 ROM 타일**을 기록해 두고,
이후에는 **에뮬 없이** 임의 롬으로 그 화면을 다시 그려 픽셀 회귀검사한다.

기록은 **에뮬 1회**, 검사는 **에뮬 0회 · 0.2초**다.

## 왜 필요했나

정적 아이템 스캐너(그림 아이템 254종 전수 렌더)는 세 가지를 원리적으로 놓친다.

1. 타일이 스캔 창(`0x1D0000~0x1FFFFF`) 밖으로 이주하면 아이템이 통째로 안 잡힌다 — SS2 전수 스캔에서 16개 확인
2. 아이템 테이블을 안 거치고 타일을 직접 읽는 화면(나찰 판 유형)은 정적으로 영원히 안 보인다
3. 구버전 세이브스테이트의 VRAM 잔존 때문에 눈 검수로도 속는다

관측은 **화면에 뜬 것만 본다.** 위 세 가지가 사라진다.
실제 기록 6화면의 커버리지 749개 중 **630개(84.1%)가 정적 스캔 창 밖**이었다.

```
$ python3 coverage.py rec_ss2 --window 1D0000:200000
화면에 실제로 뜬 고유 ROM 타일 주소: 749개  (0x01678A ~ 0x1EFC10)
정적 스캔 창 0x1D0000~0x200000 밖: 630개 / 749개 (84.1%)
```

## 실측 확정한 VRAM 구조 (beetle-ngp, SS2)

문서에 없던 것을 프레임버퍼와 대조해 확정했다.

```
0x8032/33  SCR1 스크롤 X/Y      0x8034/35  SCR2 스크롤 X/Y
0x8300     스크롤 팔레트 (팔레트당 색 4개 × u16 RGB444)
0x9000     SCR1 타일맵 32×32 u16   ← SS2는 여기가 텍스트 평면
0x9800     SCR2 타일맵 32×32 u16   ← 배경 그림
0xA000     타일 패턴 512장 × 16B (2bpp, 행당 u16, 상위비트부터)
엔트리     pattern = v & 0x1FF
```

확정 방법: **아는 정답을 심어놓고 포맷을 역산했다.**
「괴제 강림」을 보수하며 `0x1EF9C0`에 심은 타일이 VRAM 어느 슬롯에 올라갔는지
내용 대조로 찾고, 그 슬롯을 참조하는 타일맵 엔트리를 역추적해 비트필드를 확정했다.
포맷 후보 대조 코드는 `ngp_vram.py`의 `fit_format()`에 남겼다.

## 쓰는 법

```bash
# 1) 기록 (에뮬 1회) — 세이브스테이트가 필요하다
python3 observe.py 신판.ngc rec_ss2/ screens_ss2.json --sav-dir ~/ss2_sav

# 2) 회귀검사 (에뮬 0회)
python3 regress.py rec_ss2/ 구판.ngc 신판.ngc diff_img/

# 3) 버전 사다리 — 한 화면을 여러 판으로 나란히
python3 ladder.py rec_ss2/최종장타이틀.json out.png v0.63.ngc v0.95.ngc v0.98b.ngc v0.99b.ngc

# 4) 커버리지 — 정적 스캐너 사각지대 확인
python3 coverage.py rec_ss2/ --window 1D0000:200000 --list
```

필요한 것: `numpy`, `pillow`. 기록 단계만 추가로 `SS1_SamuraiShodown_NGP/emulator/`의
beetle-ngp 하네스와 코어 `.so`가 필요하다.

- `rec_ss2/*.json` — 화면별 타일맵 + `VRAM슬롯 → ROM주소` 지도 (ROM 데이터는 안 들어 있다)
- `rec_ss2/_coverage.json` — 그 화면들에 **실제로 뜬 ROM 타일 주소 전체**
- 세이브스테이트는 저장소에 없다. `screens_ss2.json`의 `sav` 이름대로 각자 만들어 `--sav-dir`에 둔다

## 검증 — 에뮬 없이 파손 이력이 재현된다

v0.99b에서 뜬 최종장 타이틀 기록 하나로 네 판을 오프라인 재렌더한 결과다.

![버전 사다리](verify_final_chapter.png)

| 롬 | 결과 |
|---|---|
| v0.63 | 명판만, 글자 없음 — 「괴제 강림」 파손 재현 |
| v0.95 | 같음 (v0.96에서 고쳐지기 전) |
| v0.98b | **「최종장 / 괴제 강림」 정상** (붓글씨 서체) |
| v0.99b | 정상 |

회귀검사도 같은 기록으로 돈다. 고친 화면 2개만 차이가 나고 나머지는 정확히 0이다.

```
$ python3 regress.py rec_ss2 v0.95.ngc v0.99b.ngc
서장타이틀          픽셀차   2480  바뀐타일  50  <-- 차이
유파선택           픽셀차      0  바뀐타일   0
전투             픽셀차      0  바뀐타일   0
최종장타이틀         픽셀차   2205  바뀐타일  48  <-- 차이
캐릭선택           픽셀차      0  바뀐타일   0
타이틀메뉴          픽셀차      0  바뀐타일   0
차이난 화면 2개

$ python3 regress.py rec_ss2 v0.98b.ngc v0.99b.ngc
차이난 화면 0개
```

차이 이미지는 위가 구판, 아래가 신판이다. 왼쪽이 SCR1(텍스트), 오른쪽이 SCR2(배경).

![회귀 차이 예시](verify_regress_example.png)

**이 검사가 있었으면 나코루루 이름판도 괴제 강림도 자동으로 걸렸다.**

## 한계 (정직하게)

- **방문하지 않은 화면은 여전히 안 잡힌다.** 커버리지를 자동화할 뿐 완전성을 주지는 않는다
- 스프라이트·애니메이션·스크롤 합성은 재현 대상이 아니다. 텍스트 평면만 정확하다
- 팔레트 뱅크가 화면마다 달라 **색 재현은 미완**이다. 회귀 비교는 회색조라 결과에 영향이 없다
- 시뮬레이터는 **기록된 타일맵을 고정**하고 롬만 갈아 끼운다. 구판에서 타일이 다른 주소에
  있었다면 그 자리는 빈 칸으로 나온다 — 파손·이주를 드러내는 데는 정확하지만,
  구판 실기 화면과 픽셀까지 같다는 뜻은 아니다
- 런타임에 만들어진 타일(ROM에 같은 16B가 없는 것)은 기록에서 빠진다
