## 2. 텍스트 엔진 — 이스케이프 시스템

한 글자 = **2바이트** `[페이지 코드][인덱스]`. 인덱스는 짝수만, 글리프 주소 = `page_base + index*16`.

| 페이지 | base | 실장 (v0.22) | 빈 슬롯 |
|---|---|---|---|
| F1 | `0x1F1C00` | 111 | 17 |
| F2 | `0x1F3B00` | 100 | 28 |
| F3 | `0x1F5A00` | 100 | 28 |
| F4 | `0x1F7900` | 100 | 28 |
| F5 | `0x1F9800` | 100 | 28 |
| F6 | `0x1FB700` | 100 | 28 |
| F7 | `0x1FD600` | **19** | **109** |

합계 **630자 · 빈 슬롯 266칸.** stride 는 전 페이지 `0x1F00`.
**홀수 인덱스 자리는 7페이지 전부 완전히 비어 있다** (실측) — 엔진이 짝수만 쓰는 이유다.

### 제어 코드 — v2.2 인계서에서 **빠져 있던 것 포함**

| 코드 | 뜻 |
|---|---|
| `0x00`–`0x19` | **대문자** A–Z |
| **`0x1A`–`0x33`** | **소문자 a–z** ← v2.2 인계서에 없다 |
| `0xD0`–`0xD9` | 0–9 |
| `0x8A` | `!` |
| **`0x8E`** | **`'`** ← v2.2 인계서에 없다 |
| **`0x8F`** | **`,`** ← v2.2 인계서에 없다 |
| `0x90` | `.` |
| `0x91` | `?` |
| `0x92` | 공백 — **인덱스로 절대 쓰지 말 것** |
| `0xF8` | 줄바꿈 |
| `0xF9` `0xFA` | 후행 제어 (좌표·연출) |
| `0xFF` | 블록 종결 |

**소문자를 모르면 영문 원문이 통째로 안 읽힌다.** 원문 대부분이 소문자이고(`e` 만 1,697회),
영문 원문은 한글 판독을 검증하는 유일한 외부 기준이다. 이걸 빼면 검수 자체가 성립하지 않는다.

**원본 롬을 디코드할 때는 `0xF1`~`0xF7` 을 페이지 코드로 읽으면 안 된다.**
원본에는 한글이 없어 그 바이트는 다른 뜻이고, 페이지로 오인하면 뒷바이트까지 삼켜
영문이 깨진다. `lb_extract.tokens(..., pages=False)` 가 이걸 처리한다.

### 문자열 교체 규칙 (등길이 원칙)

블록 구조는 `본문 + 후행 제어(F9/FA) + 0xFF`. 패딩 `0x92` 는 **후행 제어 앞**에 넣는다.
뒤에 넣으면 좌표 제어가 밀려 대사가 화면 밖으로 나간다.

> **함정 — 후행 제어는 여러 바이트다.** `{FA}{F9}` 처럼 붙어 나오므로 뒤에서 한 개만
> 떼어내면 패딩 자리를 못 찾는다. 그러면 도구가 어절 사이 공백을 패딩으로 오인해
> **문장 한가운데가 벌어진다**(「되고␣␣␣␣␣싶어요」). `lb_patch.fit()` 은 `0xF8` 이상이
> 이어지는 동안 거슬러 올라가 그 앞에만 넣는다.

## 3. 그래픽 구조

### 타일 포맷
8×8, 2bpp, 16 B/타일. 한 행 = 2 B **리틀엔디안**.
```python
w = rom[a + y*2] | (rom[a + y*2 + 1] << 8)
pixel(x) = (w >> (14 - 2*x)) & 3      # 0–3, 0은 투명
```
바이트 순서를 빅엔디안으로 읽으면 글자가 깨져 나온다. 초기 분석에서 여기 시간을 많이 썼다.

### VRAM 맵 (CPU 주소)
| 주소 | 용도 |
|---|---|
| `0x8800` | 스프라이트 |
| `0x8032`–`0x8035` | 스크롤 레지스터 |
| `0x9000` | SCR1 타일맵 (32열 × 2 B) |
| `0x9800` | SCR2 타일맵 |
| `0xA000` | 타일 데이터 (512 × 16 B) |

맵 엔트리: 하위 9비트 = 타일 번호, 상위 = 플립/팔레트 플래그.

### 3-B. 팔레트 존 (v2.2 실측 — 원 데이터는 유실)

값 1/2/3 → 실제 색의 매핑이 화면 영역마다 다르다. 로고 영역만 10종.
원작 로고의 화염 그라데이션은 그림이 아니라 **팔레트 존 배치**의 결과다.

| 존 | 값1 | 값2 | 값3 |
|---|---|---|---|
| `00` | 크림 | 파랑 | 네이비 |
| `02` | 크림 | 주홍 | 적갈 |
| `04` | 주황 | 주홍 | 네이비 |
| `06` | 주황 | 적갈 | 네이비 |
| `08` | 살구 | 크림 | 네이비 |
| `11` | 크림 | 주홍 | 네이비 |
| `13` | 크림 | 적갈 | 네이비 |
| `15` | 살구 | 회갈 | 네이비 |
| `17` | 주황 | 크림 | 네이비 |
| `19` | 주홍 | 살구 | 네이비 |

> **주의 — 이 표는 v2.2 인계서에서 옮겨 적은 것이고 `probe_map.json` 원본은 유실됐다.**
> 이번 작업에서 재측정하지 않았다. 로고나 그래픽을 다시 손볼 때는
> **먼저 다시 재야 한다.** 방법: 대상 셀에 값 1/2/3 스트라이프 타일을 써넣은 프로브 롬을
> 만들어 자연 부팅 → 타이틀 스샷을 1× 로 리샘플 → 셀별 RGB 를 읽는다.
> 코어가 `retro_ngp_charram`/`palram` 등을 export 하므로 `dlsym` 으로 직접 읽는 편이 빠르다.

## 4. 함정 목록 — 먼저 읽을 것

### 4-A. 왕복 검사는 판독의 **정확성**을 증명하지 못한다 ★ v0.22 최대 교훈

해독한 문장을 다시 인코딩해 원본 바이트와 대조하는 검사는
**「판독표가 자기 자신과 일관되는가」만 본다.** 글리프 하나를 처음부터 끝까지 똑같이
잘못 읽으면 왕복은 100% 통과한다 — 판독표 자신이 기준이기 때문이다.

실제로 v0.22 작업에서 **왕복 일치 402·중복 0 으로 「판독 확정」을 선언한 뒤에도
글리프 10개를 잘못 읽고 있었다.** 중복 음절 검사도 서로 다른 두 오독은 못 잡는다.

**오독을 잡는 것은 영문 원문 문맥이다.** 「일●이 243인을 벤 대검호」가 「일찍이」를
요구하는데 판독표가 「일꺽이」를 내놓으면 그 자리가 곧 오독이다.
`lb_context.py` 가 슬롯마다 「자형 그림 + 그 글자가 든 문장(대상은 ●로 가림) + 영문 원문」
카드를 만든다. **최종 확정은 실기 화면**이다.

### 4-B. 8×8 한글 자형 판정 규칙 (실측)

세로 모음은 **5열**(0-based)에 세로줄로 선다.

| 모음 | 판정 |
|---|---|
| **ㅏ / ㅑ / ㅘ** | **6열(오른쪽)에 획이 있다** |
| **ㅓ / ㅕ / ㅣ** | **6열이 비어 있다** |
| ㅓ vs ㅕ | 4열(왼쪽) 곁획이 **1개면 ㅓ, 2개면 ㅕ** |

곁획이 0·2행에 오느냐 1·3행에 오느냐는 글자마다 다르지만 **개수는 예외 없다.**
가로 모음(ㅗ ㅜ ㅡ)은 폭 넓은 가로줄로 나오고 초성이 그 위에 2줄로 눌린다.
겹자음(ㄲ ㄸ ㅃ ㅆ ㅉ)은 같은 모양이 가로로 두 번 눌려 획이 촘촘해진다.

**초성이 다른 글자끼리 곁획 위치를 비교하면 안 된다.** ㅌ 은 가로바가 4열까지 뻗어
ㅂ 글자의 ㅓ 곁획과 같은 자리에 점이 찍힌다. 판정은 **같은 초성끼리** 한다
(이 착각으로 `F1:88` 판정이 한 번 뒤집혔다가 ㅂ 초성 전수 대조로 확정됐다).

### 4-C. 원 제작자의 「글자 대체」를 오독과 헷갈리지 말 것

폰트에 없는 글자를 비슷한 것으로 때운 자리가 따로 있다. 판별법은 간단하다 —
**폰트에 정답 글자가 있으면 진짜 결함, 없으면 대체다.** 대체는 빈 슬롯에 글리프를 그려 고친다.

v2.2 까지 남아 있던 대체: 벌→별, 접→(DIRECT 그대로).

### 4-D. 글리프 충돌 — v2.2 인계서 §4-C 정정

v2.2 인계서는 「비트맵이 같아지는 그룹이 287개」라며 디코더가 뱉는 오타의 상당수가
가짜라고 경고한다. **그건 폰트 전체 음절 공간의 이론적 충돌이고, 롬에 실린 630자끼리는
중복이 2종뿐이다.**

| 글자 | 슬롯 |
|---|---|
| 런 | `F1:D4` `F6:82` (비트맵 동일) |
| 별 | `F1:88` `F6:B4` (비트맵 동일) + `F3:84` (자형이 조금 다른 별도 그림) |

왕복 검사의 불일치 8건은 전부 이 중복 중 **어느 슬롯을 고르느냐의 차이**이고
화면 출력은 같다. `lb_verify.KNOWN_DUP` 에 예외로 등록돼 있다.

### 4-E. 스테일 VRAM

세이브스테이트를 로드하면 **예전 타일이 복원**된다. 타이틀 계열 검증은 반드시
**자연 부팅**으로 한다 (약 4,800 프레임). 상태를 불러오면 롬 수정이 화면에 안 나타난다.

### 4-F. 공유 타일

같은 타일이 여러 화면에서 재사용된다. 한쪽만 고치면 다른 쪽이 깨진다.
특히 **ASCII 폰트는 롬 전체에 한 벌뿐**이라(`0x5C840`–`0x5CD00`) 절대 덧칠 금지 —
`TM`·`©SNK`·`PLAYER 1`·`Pow`·`RESULT` 가 전부 이 폰트를 쓴다.

이름판은 이름별이 아니라 **글자별 세로 폰트**를 공유한다.

### 4-G. 블라인드 내비게이션 타이밍

메뉴가 뜨는 데 지연이 있어 고정 프레임 딜레이는 어긋나기 쉽다.
**타이틀에서 메뉴를 여는 것도, 메뉴에서 확정하는 것도 NGP A 버튼**이고
하네스 토큰으로는 `B` 다 (NGP A = 레트로 B, NGP OPTION = `ST`).
검증된 순서는 `boot_*.txt` 스크립트에 있다.

### 에뮬레이터 하네스

```
gcc -O2 -o ngprun ngprun.c -ldl -lm
./ngprun ./core.so <rom> <script> <출력접두사>
```

코어는 `core.so` (beetle-ngp libretro, x86_64). 스크립트 한 줄:

| 구문 | 뜻 |
|---|---|
| `<프레임> <버튼…>` | 버튼을 누른 채 그만큼 진행 |
| `!<태그>` | 그 시점 화면(.ppm)과 RAM(.ram) 덤프 |
| `!save f` / `!load f` | 상태 저장·복원 (**타이틀 검증엔 쓰지 말 것**) |
| `!poke HEX=DEC` / `!unpoke` / `!peek HEX` | 롬 바이트 조작·조회 |

버튼 토큰: `U D L R A B X Y ST SE L1 R1`. **NGP A = `B`, NGP OPTION = `ST`.**

> **`retro_set_controller_port_device` 를 반드시 호출해야 한다.** 안 하면 입력이 통째로
> 무시돼 메뉴를 못 넘긴다. 이것 때문에 하네스가 한 번 죽었다.

준비된 부팅 스크립트: `boot_intro.txt`(인트로 21장) `boot_menu.txt`(타이틀·메뉴)
`boot_option.txt`(게임 설정) `boot_story.txt`(모드→캐릭터→전투).

## 8. 검수 결과 요약

499블록을 영문 원문과 줄 단위로 대조했다. **첫 지적 61건 중 14건은 결함이 아니라
판독 오류였다.** 판독표 10슬롯을 고쳐 해소했다.

| 잘못 읽음 | 실제 | 자형 근거 |
|---|---|---|
| 첨 | **참** | 6열에 획 → ㅏ |
| 늪 | **늙** | 종성 밑줄 비대칭 → ㄺ |
| 꺽 | **찍** | 초성 다리가 벌어짐 → ㅉ |
| 콘 | **론** | 1행이 5열에서 끊겨 ㅋ 불가 |
| 컨 | **권** | 2~4행이 「원」의 ㅝ와 동일 |
| 쫓 | **좇** | 초성이 홑 ㅈ |
| 씩 | **씌** | 5행 전폭 가로줄 = ㅡ |
| 릴 | **틸** | 초성이 ㅌ |
| 벌 | **별** | 4열 곁획 2개 (`F1:88`·`F6:B4`) |

### 결함 아님으로 판정한 것

- **메뉴 줄 간격 겹침** — 원본도 똑같다(`1P PLAY`/`VS PLAY` 도 붙어 있음).
- **「1인 홀레이」** — 8배 확대하면 「1인 **플**레이」로 정확하다. 저해상도 착시였다.
- **「황룡」** — 자형에 ㅘ가 뚜렷해 홍룡이 아니다. 사신 구도의 중앙 황룡과도 맞는다.
- **`007751` 「A선택 누락」** — 실제 바이트는 `A{9A}선택  B{9A}종료` 로 A 가 이미 있다.
  제어바이트를 지우고 본 탓에 빠진 줄 알았던 오탐이다.
- **`F2:C0` 「할」의 여분 픽셀** — 1행 4열에 점이 하나 더 있어 다른 ㅎ 글자와 어긋나지만
  판독·표시에는 영향이 없다. 글리프를 손볼 때 같이 지우면 좋다.
