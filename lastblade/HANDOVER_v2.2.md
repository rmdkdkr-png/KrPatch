## 2. 텍스트 엔진 — 이스케이프 시스템 (완전 해독)

한 글자 = **2바이트**. `[페이지 코드][인덱스]`

```
페이지 코드 : F1 F2 F3 F4 F5 F6 F7
인덱스      : 짝수만 (0x00, 0x02, 0x04 …)
글리프 주소 : page_base + index * 16
```

| 페이지 | base | 실장 글리프 |
|---|---|---|
| F1 | `0x1F1C00` | 106 |
| F2 | `0x1F3B00` | 100 |
| F3 | `0x1F5A00` | 100 |
| F4 | `0x1F7900` | 100 |
| F5 | `0x1F9800` | 100 |
| F6 | `0x1FB700` | 100 |
| F7 | `0x1FD600` | 17 (여유 83) |

stride 는 전 페이지 `0x1F00` 로 균일. **F6·F7은 초기 분석에서 누락됐던 페이지**로, 덤프 아티팩트를 역추적해 발견·의미 검증한 것이다. 새 페이지가 더 있는지는 F7 뒤 `0x1FF500` 부근을 확인할 것.

### 제어 코드
| 코드 | 뜻 |
|---|---|
| `0x92` | 공백 — **인덱스로 절대 쓰지 말 것** (아래 참조) |
| `0xF8` | 줄바꿈 |
| `0xF9`, `0xFA` | 후행 제어 (좌표·연출) |
| `0xFF` | 블록 종결 |
| `0x00`–`0x19` | A–Z |
| `0xD0`–`0xD9` | 0–9 |
| `0x8A` `!` / `0x90` `.` / `0x91` `?` | 기호 |

**함정**: 인덱스 `0x92`는 공백 코드와 충돌해 사용 금지. 글리프 자동 할당기(`free_slot()`)에 스킵 로직이 들어 있다. 이 가드를 지우면 특정 글자에서 문장이 조용히 잘린다.

### 문자열 교체 규칙 (등길이 원칙)
블록 구조는 `본문 + 후행 제어(F9/FA) + 0xFF`.
패딩 `0x92`는 **후행 제어 앞**에 넣는다. 뒤에 넣으면 좌표 제어가 밀려 대사가 화면 밖으로 나간다.
바이너리 좌표 프리픽스는 **원문 그대로 보존**한다.

### 사전
- `bank_map.json` — 한글 → `[페이지, 인덱스]` (인코딩, 627항목)
- `inv_map.json` — `"F100"` → 한글 (디코딩, 623항목)

## 3. 그래픽 구조

### 타일 포맷
8×8, 2bpp, 16 B/타일. 한 행 = 2 B 리틀엔디안.
```python
w = rom[a+y*2] | (rom[a+y*2+1] << 8)
pixel(x) = (w >> (14 - 2*x)) & 3      # 값 0–3
```
값 0은 투명. 1·2·3의 **실제 색은 팔레트 존에 따라 다르다** (§3-B).

### VRAM 맵 (CPU 주소)
| 주소 | 용도 |
|---|---|
| `0x8800` | 스프라이트 |
| `0x8032`–`0x8035` | 스크롤 레지스터 |
| `0x9000` | SCR1 타일맵 (32열 × 2 B/엔트리) |
| `0x9800` | SCR2 타일맵 |
| `0xA000` | 타일 데이터 (512개 × 16 B) |

맵 엔트리: 하위 9비트 = 타일 번호, 상위 = 플립/팔레트 플래그.

### 3-B. 팔레트 존 — v2.2의 핵심 발견

**값 1/2/3 → 실제 색의 매핑이 화면 영역마다 다르다.** 로고 영역만 해도 10종.
원작 로고의 빨강→주황 화염 그라데이션은 그림이 아니라 **팔레트 존 배치**로 만들어진 것이다.

실측표 (타이틀 로고 영역, `probe_map.json`):

| 존 | 값1 | 값2 | 값3 |
|---|---|---|---|
| `00` | 크림 | **파랑** | 네이비 |
| `02` | 크림 | 주홍 | **적갈** |
| `04` | **주황** | 주홍 | 네이비 |
| `06` | 주황 | 적갈 | 네이비 |
| `08` | 살구 | 크림 | 네이비 |
| `11` | 크림 | 주홍 | 네이비 |
| `13` | 크림 | 적갈 | 네이비 |
| `15` | 살구 | 회갈 | 네이비 |
| `17` | 주황 | 크림 | 네이비 |
| `19` | **주홍** | 살구 | 네이비 |

**측정 방법 (재현 가능)**: 대상 셀 전체에 값 1/2/3 스트라이프 타일을 써넣은 프로브 롬을 만들고 → 자연 부팅 → 타이틀 스샷을 1× 로 리샘플 → 셀별 스트라이프 행의 RGB를 읽는다. 코드 흐름은 `logo8.py` 하단 `ZPAL` 블록.

**작업 규칙**: 의미색(크림/빨강/네이비)으로 그림을 그린 뒤, 셀의 존을 보고 값으로 **역매핑**한다. 존을 무시하고 값을 직접 쓰면 글자가 배경색으로 칠해져 사라진다. 본체색과 림색이 같은 값으로 매핑되면 림을 차선값으로 밀어 윤곽을 살린다.

## 4. 함정 목록 — 반드시 먼저 읽을 것

### 4-A. 공유 타일 (최대 사고 원인)
같은 타일이 여러 화면·여러 좌표에서 재사용된다. 한쪽만 고치면 다른 쪽이 깨진다.

| 타일/영역 | 공유 상황 |
|---|---|
| 헤더 풀 `05F1ED`–`05F22D` | Select 등 상단 UI 공용 |
| **이름판 풀** | 이름별이 아니라 **글자별 세로 폰트** 공유 (KAEDE의 E, K는 YUKI와 공유) → **구조적으로 번역 불가** |
| 인트로 `08CC76`, `08CD76` | 인트로 프레임 간 공유 |
| 엠블럼 `08C306` | 3개 화면 계열이 공유 |
| CONTINUE `064634` | r7에서 같은 타일이 2셀에 표시 |
| 로고 `t040` = `08A150` | **(r6,c10)과 (r7,c10)에 동시 표시** |

로고 `t040` 대응 사례: 그 자리에 "세로로 균일한" 칼 장식을 세워, 두 행에 같은 내용이 나와도 자연스럽게 보이도록 **제약을 디자인으로 흡수**했다. `logo8.py`에 `공유타일 일치: True` 자동 검증이 들어 있다.

### 4-B. 로고 제약 셀 (플립·재사용)
아래 타일은 뒤집혀 재등장하므로 반드시 **공백 처리**한다:
`089F10` (r4c2 정상 + r10c5 hv플립), `08A1E0` (r7–9에 3회), `08A6E0`/`08A6F0`/`08A700` (r11–12 플립).
`r12 c18–19`는 폰트 타일이므로 **건드리지 말 것**.

### 4-C. 갈무리 8×8 글리프 바이트 충돌
8×8로 축소하면 서로 다른 음절의 비트맵이 **완전히 같아지는 그룹이 287개** 있다 (획=횤, 좋=쯯, **홈=홉**, 궂=긏 …).
→ 디코더가 뱉는 "오타"의 상당수는 **가짜**다. 바이트가 같으면 화면 출력도 같으므로 고칠 것이 없다.
→ 단, `쨰 ≠ 째`처럼 **진짜 다른** 경우가 섞여 있다 (F7,08 타일 교체로 수정 완료). 충돌표를 만들어 대조한 뒤에 판단할 것.

### 4-D. 스테일 VRAM
세이브스테이트를 로드하면 **예전 타일이 복원**된다. 타이틀 계열 검증은 반드시 **자연 부팅**으로 한다 (~4,200–4,500 프레임). 감지 코드는 §5.

### 4-E. 블라인드 내비게이션 타이밍
고정 프레임 딜레이는 어트랙트 주기와 어긋난다. `press_until_change` / `wait_stable` / 상태 감지 루프를 쓰고, 검증된 세이브 경로(`st/*.sav` → B 연타)를 재사용한다.

## 5. 검증 절차 (릴리스 전 필수)

### 5-1. 타이틀 자연 부팅 감지
```python
def on_title():
    d = e.read(0x9000 + 15*64, 64)      # SCR1 r15
    t = (d[6] | (d[7] << 8)) & 0x1FF    # c3 엔트리
    if not t: return False
    b = bytes(e.read(0xA000 + t*16, 16))
    if b == b'\x00'*16: return False
    return 0x5C900 <= ROM.find(b) < 0x5CA00   # PRESS-A 'P' 타일 출처
```
`e.run(3900)` 후 30프레임씩 돌리며 감지 → `e.run(150)` → 스샷 6~8장 → **채도 최대 프레임**을 고른다 (페이드 중간 프레임 회피).

### 5-2. IPS 라운드트립
IPS 생성 후 원본에 재적용해 패치 롬과 **바이트 완전 일치**를 확인한다. 오프셋 `0x454F46`("EOF")과 충돌하는 레코드는 1바이트 당겨 회피한다.

### 5-3. 회귀
인트로 어트랙트 전 구간 스샷(약 26장)을 떠서 타일 오염이 없는지 확인. 로고 타일은 인트로와 공유 영역이 인접하므로 이 검사를 생략하지 말 것.

### 5-4. 설계 단계 자동 검증 (`logo8.py`)
- `본체/림 소실: 0` — 그린 글자가 실존 셀 밖으로 나가지 않았는지
- `공유타일 일치: True` — 공유 타일의 두 표시 위치 내용이 같은지
