# SVC MotM 한글판 v17.2 — 잔여 원본 타일 조사

`tools/tiletool/`로 조작 경로 9화면을 관측하고, 원본 롬 `SNK Vs Capcom - Match of The
Millennium (JUE) [!]`와 대조한 결과다. 조사일 2026-08-24.

판정은 주소가 아니라 **내용**으로 한다. 화면에 뜬 타일의 16바이트가 원본 롬 어디에도
없으면 새로 그린 타일이다. (4MB 롬에서는 같은 타일이 여러 주소에 중복돼 주소 비교가 흔들린다.)

```bash

python3 tools/tiletool/diffmap.py rec_svc/ 원본.ngc SVC_kr_v17.2.ngc \
        --lines 줄/ --min-run 4 --csv 남은것.csv
```

## 머리글 조사 기록

> **정정.** 이 절에는 한때 「`GAME SELECT`·`STYLE SELECT` 는 막혔다」고 적혀 있었다.
> 틀렸다. 도안과 화면을 픽셀로 대조해 보니 그때 이미 맞게 나오고 있었고,
> 검증용 잘라내기가 머리글을 화면 밖으로 잘라먹고 있었을 뿐이다.
> 지금은 셋 다 나오고 [`check_headers.py`](../tools/svc/check_headers.py) 가 자동으로 대조한다.
> 아래는 그 과정에서 알아낸 구조와, 실제로 헛다리였던 것들이다.

### 구조

세 머리글은 **하나의 스프라이트 타일 풀**(`0x22A800`~`0x22AF00`, 112장)을 나눠 쓴다.
풀의 타일마다 번호를 점으로 심은 롬을 만들어 화면에서 읽어 확정했다.

    MAIN MENU     타일 0~26    (0x22A800~0x22A9A0)
    STYLE SELECT  타일 27~62   (0x22A9B0~0x22ABE0)
    GAME SELECT   타일 64~98   (0x22AC00~0x22AE20)

y 값이 여러 개로 나오는 것은 애니메이션이 아니다. 글자 띠의 **비스듬한 끝동강**이
별도 스프라이트로 붙기 때문이고, 글자 자체는 가로 한 줄이다.
(정지 900프레임까지 지켜봐도 좌표가 안 변한다 — 애니메이션이 아니다.)

### 실제 제약 두 가지

**화면끼리 공유되는 띠 타일이 있다.** 한 화면 기준으로 띠를 다시 그려 써 넣으면 다른 두
화면의 띠가 같이 깨진다 — 세 화면을 한 롬에 구웠다가 셋 다 깨뜨려 봤다. 하지만 겹치는 건
**본체가 아니라 띠 끝동강 몇 장**(99·102 등)뿐이다. 그건 글자가 없는 장식이라 원판 그대로
두면 그만이고, 세 화면의 본체 구간(0~26 / 27~62 / 64~98)은 서로 안 겹친다.
「막혔다」고 본 것은 이 구분을 안 하고 풀 전체가 공유된다고 넘겨짚었기 때문이다.

**한 화면 안에서도 타일이 겹친다.** `MAIN MENU` 는 32칸이 고유 타일 30장만 쓴다
(`MAIN` 의 M 과 `MENU` 의 M 이 같은 타일). 그 칸에 서로 다른 그림을 넣으면 나중 쓰기가
앞을 덮어 두 칸 다 어긋난다 — 6칸이 깨졌다. 빌더는 **어절을 좌우로 밀어 가며** 겹친 칸의
그림이 같아지는 조판을 찾아 푼다(−1px 로 풀렸다). 비교는 마스크가 아니라 **그린 결과**로
해야 한다 — 외곽선은 칸 경계를 넘어 번진다.

### 헛다리 네 개 (다시 하지 말 것)

1. **주소를 내용으로 찾기** — 띠 타일은 여러 장이 내용이 같아서 첫 일치를 쓰면
   남의 자리에 글자를 써 넣는다. 번호를 심어 화면에서 읽어야 한다
2. **띠를 끝동강 사이로 보간** — 끝동강이 뾰족해서 가운데가 얇아진다
3. **띠 범위를 파란 픽셀로만 재기** — 글자에 가린 열은 파란 픽셀이 없다.
   **원판 글자가 있던 자리도 띠에 포함**시켜야 원래 두께가 나온다
4. **화면을 잘라서 검증하기** — 머리글 y좌표는 화면마다 다르다(`MAIN MENU` y=6,
   `STYLE SELECT` y=4, `GAME SELECT` y=13). 고정 잘라내기로 보면 멀쩡한 것도 깨져 보인다.
   **스프라이트 좌표 그대로** 합성해 비교해야 한다

### PLAYER SELECT 는 타일맵이다

같은 「머리글」이지만 구조가 다르다. `SCR1` 행0~1 × 열1~18 에 뜨고 타일은 `0x31F810` 부터
**연속 36장**인 스트립이다 — 이름판과 같은 모양이라 스프라이트 도구가 아니라
[`build_player_ko.py`](../tools/svc/build_player_ko.py) 로 따로 처리했다.

파란 띠도 성질이 다르다. 메뉴 머리글은 띠가 글자보다 두꺼워 "원판 글자 자리도 띠"로 잡았지만,
여기는 띠(6px)가 글자(11px)보다 얇아 같은 규칙을 쓰면 띠가 부푼다. 대신 **띠가 보이는 열에서
끝을 읽고 가린 열은 보간**한다 — 144열 중 80열이 띠를 직접 보여 주므로 안전하다.
**규칙을 옮겨 쓰기 전에 그 규칙이 왜 그랬는지를 확인해야 한다.**
